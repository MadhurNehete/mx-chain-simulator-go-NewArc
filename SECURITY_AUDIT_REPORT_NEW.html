1. Unbounded Resource Consumption (DoS)

Severity: High | CWE: CWE-400 (Uncontrolled Resource Consumption)

Technical Description

The simulator's API provides endpoints to generate blocks or progress epochs. These functions wrap the core simulator logic and are protected by a global synchronization mutex. The implementation failed to validate integer inputs. An attacker can submit a request with an extremely large block count, forcing a massive CPU-bound loop while holding the global lock.

Operational Impact

A single malicious request will cause the simulator process to consume 100% CPU and block all other API requests indefinitely. This results in a total Denial of Service (DoS).

Vulnerable Code (Before): 
func (sf *simulatorFacade) GenerateBlocks(numOfBlocks int) error {
    if numOfBlocks <= 0 {
        return errInvalidNumOfBlocks
    }
    return sf.simulator.GenerateBlocks(numOfBlocks)
}
Remediated Code (After): 
func (sf *simulatorFacade) GenerateBlocks(numOfBlocks int) error {
    if numOfBlocks <= 0 || numOfBlocks > maxBlocksToGenerate {
        return fmt.Errorf("invalid blocks count (max: %d)", maxBlocksToGenerate)
    }
    return sf.simulator.GenerateBlocks(numOfBlocks)
}

2. Symlink Following in Config Fetching

Severity: Medium | CWE: CWE-59 (Improper Link Resolution)

Technical Description

The copyFolderWithAllFiles function recursively traverses directories but follows symbolic links by default. If a repository contains a symlink pointing to a file outside the repository, the simulator will copy the contents of the target file into its workspace.

Operational Impact

This is an Arbitrary File Read vulnerability. Attackers can exfiltrate sensitive host-level files (SSH keys, credentials) by making them available within the simulator's workspace.

Vulnerable Code (Before): 
return filepath.Walk(src, func(path string, info os.FileInfo, err error) error {
    if info.IsDir() {
        return os.MkdirAll(filepath.Join(dst, relPath), info.Mode())
    }
    in, err := os.Open(path)
    // ... logic blindly copies file contents
})
Remediated Code (After): 
return filepath.Walk(src, func(path string, info os.FileInfo, err error) error {
    if info.Mode()&os.ModeSymlink != 0 {
        return nil // Securely skip symbolic links
    }
    if info.IsDir() {
        return os.MkdirAll(filepath.Join(dst, relPath), info.Mode())
    }
    // ... rest of secure copy
})

3. Insecure Container Configuration (Root)

Severity: Medium | CWE: CWE-250 (Execution with Unnecessary Privileges)

Technical Description

The Dockerfile does not define a non-root user, causing the simulator to run with UID 0 (root) inside the container. This violates the principle of least privilege.

Operational Impact

Running as root increases the blast radius of any exploit. It facilitates container escapes, unauthorized host volume access, and lateral movement within the network.

Vulnerable Code (Before): 
FROM ubuntu:22.04
COPY --from=builder /bin/chainsimulator /multiversx/
ENTRYPOINT ["./chainsimulator"]
Remediated Code (After): 
FROM ubuntu:22.04
RUN groupadd -r simulator && useradd -r -g simulator simulator
RUN chown -R simulator:simulator /multiversx
USER simulator
ENTRYPOINT ["./chainsimulator"]

4. Sensitive Data Persistence in /tmp

Severity: High | CWE: CWE-312 (Cleartext Storage of Sensitive Information)

Technical Description

The simulator generates a walletKey.pem file in a temporary directory containing unencrypted private keys. The application lacks any logic to delete these files when the process terminates.

Operational Impact

On shared machines, these private keys remain on disk indefinitely. Any user with local access can recover these keys and gain control over the simulated blockchain authority.

Vulnerable Code (Before): 
func main() {
    tempDir, _ := os.MkdirTemp(os.TempDir(), "sim-*")
    startSimulator(tempDir)
    // Application exits; tempDir remains on disk
}
Remediated Code (After): 
func main() {
    tempDir, _ := os.MkdirTemp(os.TempDir(), "sim-*")
    defer os.RemoveAll(tempDir) // Atomic cleanup on exit
    startSimulator(tempDir)
}

5. Argument Injection in exec.Command

Severity: Medium | CWE: CWE-88 (Improper Neutralization of Argument Delimiters)

Technical Description

The application uses exec.Command with arguments derived from configuration. If these strings start with a hyphen, the binary interprets them as command-line flags.

Operational Impact

An attacker who can influence the configuration can achieve Remote Code Execution (RCE) by providing a repo URL that executes arbitrary payloads.

Vulnerable Code (Before): 
cmd := exec.Command("git", "clone", repoURL, destDir)
err := cmd.Run()
Remediated Code (After): 
// Use '--' to separate flags from positional arguments
cmd := exec.Command("git", "clone", "--", repoURL, destDir)
err := cmd.Run()
